# Mobile web presentation

The web build adapts at widths up to 767 CSS pixels, and at widths up to 1023 when height is at most 500 pixels for phone landscape. A shared matchMedia state owns only presentation. Phone screens temporarily fill the viewport and use MiniBar; widening restores saved web window geometry and player style. Resizing does not save mobile choices into desktop preferences. The media listener is removed on release and replaced on reconnect.

The bottom navigation exposes Search, Favorites, and Playlists. Favorites opens the canonical love list. Playlists uses the single existing Aside/MyList tree as a full-width index, represented by `/library?id=<id>&panel=playlists`. Selecting any playlist pushes its canonical detail route, so browser Back returns to the index; Return to songs and Escape close the index. Navigation and playback remain interactive. Search restores the last online path and query, including its provider, without caching results. When no provider is available, it offers an Extensions action.

The phone header shows search only on online routes and a contextual title elsewhere. More exposes recent playback, extensions, settings, source code, and logout. Sources use a labeled native selector; provider IDs stay unchanged. Single-capability tabs are omitted. Playlist headings show title/count, Play all, and an overflow menu retaining shuffle, batch selection, find, sort, deduplication, and applicable save actions.

The existing player, queue, data, login, routes, list actions, and backend remain in use. Phone rows use a derived virtualizer height of at least 64 CSS pixels and fixed 44 pixel artwork; desktop retains the measured setting. A normal tap plays once; heart and More act independently. Batch mode selects rows and suppresses their ordinary actions; desktop double-click and modifier selection remain intact. Secondary columns are hidden. The mini player exposes favorite, queue, and play/pause; the full player retains previous/next. Expanded playback has cover/lyrics tabs, transport, seek, and queue controls. Viewport, safe areas, modal bounds, settings wrapping, and the extension store adapt to narrow widths. Selectors under html keep mobile CSS pixel geometry out of the desktop postcss-pxtorem conversion. Control hit areas and icon sizes are specified separately.

Validation should cover 320–430 pixel portrait, short landscape, keyboard/search, empty and populated lists, playlist navigation and browser Back, play/seek/queue, dialogs, extensions/settings, and widening back to desktop. Static diff inspection is included in this change; production build, browser testing, and deployment verification are performed by the integrating task. Physical iPhone Safari playback remains subject to its media policies and codec support. This change does not add an iOS application or offline playback.

The playlist index uses the opaque content background and exposes New playlist plus per-list management. The same More menu is available on route pages and the index.
